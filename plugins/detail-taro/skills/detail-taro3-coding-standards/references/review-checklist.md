# 代码审查清单（detail-taro3）

审查时结合 [conventions.md](conventions.md) 与具体 diff。下列 **严重程度** 为建议默认；若业务有特殊约定可注明。

**严重程度**：`E` = 错误（必须修复） / `W` = 警告（建议修复） / `H` = 提示（可选优化）

---

## 1. 格式与 Lint

| ID  | 检查项                                                               | 严重 |
| --- | -------------------------------------------------------------------- | ---- |
| F1  | 是否引入明显 ESLint 报错（含 `react-hooks/rules-of-hooks`）          | E    |
| F2  | `react-hooks/exhaustive-deps` 警告是否被合理处理或有意忽略并注释说明 | W    |
| F3  | 无仅因个人偏好、与项目配置冲突的格式改动（大范围无关格式化）         | W    |

## 2. TypeScript

| ID  | 检查项                                                                     | 严重 |
| --- | -------------------------------------------------------------------------- | ---- |
| T1  | 新逻辑是否在 `strictNullChecks` 下安全（空值、可选链、断言是否过宽）       | E    |
| T2  | 是否存在明显 `any` 滥用；公共导出类型是否清晰                              | W    |
| T3  | 未使用变量/参数是否清理（与 `noUnusedLocals` / `noUnusedParameters` 一致） | W    |
| T4  | 复杂结构是否有必要类型别名或注释，避免重复巨型内联类型                     | H    |

## 3. React / Taro 习惯

| ID  | 检查项                                                              | 严重 |
| --- | ------------------------------------------------------------------- | ---- |
| R1  | Hooks 是否在组件顶层调用，无违反 rules-of-hooks 的写法              | E    |
| R2  | 列表渲染 `key` 是否稳定、合理                                       | W    |
| R3  | 是否误用仅在 H5 可用的 API 于小程序/RN（跨端场景）                  | E    |
| R4  | 性能敏感路径是否存在明显无 memo 的大对象/函数内联创建（可说明理由） | H    |

## 4. 导入与路径别名

| ID  | 检查项                                                                                          | 严重 |
| --- | ----------------------------------------------------------------------------------------------- | ---- |
| I1  | 是否优先使用 `@/`、`@index/` 等同项目配置，避免不必要的 `../../../`                             | W    |
| I2  | 导入顺序、分组是否与同目录文件一致                                                              | H    |
| I3  | 是否引入禁止的第三方 UI（与 Koala 策略冲突时以 [koala-skill](../../koala-skill/SKILL.md) 为准） | W    |

## 5. 样式（Less）

| ID  | 检查项                                                                                      | 严重 |
| --- | ------------------------------------------------------------------------------------------- | ---- |
| S1  | 新建/大改样式是否遵循 BEM、嵌套与多端策略（见 [less-modular](../../less-modular/SKILL.md)） | W    |
| S2  | 是否滥用全局污染或极高优先级覆盖                                                            | W    |

## 6. 可维护性

| ID  | 检查项                                                     | 严重 |
| --- | ---------------------------------------------------------- | ---- |
| M1  | 单文件是否过长、职责过多，是否应拆分                       | H    |
| M2  | 命名是否与同模块一致（组件 PascalCase、工具 camelCase 等） | H    |
| M3  | 魔法数字/字符串是否应提取常量或枚举                        | H    |

## 7. 安全与性能（最小集）

| ID  | 检查项                                                            | 严重 |
| --- | ----------------------------------------------------------------- | ---- |
| P1  | 用户可控字符串是否直接 `dangerouslySetInnerHTML` 或未转义插入 DOM | E    |
| P2  | 网络请求错误与边界状态是否处理（空数据、失败重试视业务）          | W    |
| P3  | 是否在循环/频繁回调中做重计算或可无必要请求                       | H    |

## 8. Git 与提交说明（若审查含提交信息）

| ID  | 检查项                                                      | 严重 |
| --- | ----------------------------------------------------------- | ---- |
| G1  | `type` 是否在 commitlint 允许列表内                         | E    |
| G2  | 描述是否准确反映变更；Cursor 生成说明是否为中文（团队约定） | W    |

---

审查输出时，请引用 **ID**（如 F1、T2）便于对照 [conventions.md](conventions.md)。
